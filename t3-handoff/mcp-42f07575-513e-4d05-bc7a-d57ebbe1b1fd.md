User's example: right-clicking the desktop does not use the border colour set in Windows settings. ## What is done
1. **Root cause found and proven from the mod's own debug log.** Windows paints `MENU_POPUPBACKGROUND` (part 10) after `MENU_POPUPBORDERS` (part 9) on some menus; both parts shared one whole-clipRect `BLACKNESS` fill, so the accent frame the border branch had just drawn was erased again. Measured on winver's 165x50 menu: 0 of 430 outline pixels matched the accent. The order is unstable, which is why the ring was present on 13/10 and gone on 17/10 with the same DLL — never a version regression.
2. **Fix written** in `Windhawk\translucency-flyouts\src\30-engine.inc` (version 0.6.34). Re-verified this session by reading the file:
   - line 43 declares `RECT outlineRect{}`; line 667 sets `state->outlineRect = clipRect;` in the `MENU_POPUPBORDERS` branch (authoritative ring for the menu being painted), and that branch draws only the 1 px outline (lines 676-682) — no full-rect fill;
   - `HandleMenuDrawThemeBackground` (line 481) fills `BLACKNESS` only inside `outlineRect` inflated by -1 (lines 525-534), then at lines 540-544 re-frames with `DcStateGuard` + `SelectClipRgn(hdc, nullptr)` + `HandlePopupMenuNonClientBorderColors(hdc, state->outlineRect)`, so the outline lands on top of whichever band filled last;
