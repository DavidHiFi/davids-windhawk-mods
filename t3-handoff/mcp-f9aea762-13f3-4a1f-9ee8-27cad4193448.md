### Root cause
Windows paints MENU_POPUPBACKGROUND bands after MENU_POPUPBORDERS on some menus (proved by [dtb] part=10 then part=9 in tf-winver.exe-46284.log). Both parts shared one whole-clipRect BLACKNESS fill, so the accent frame the border branch had just drawn was erased again: 0 of 430 outline pixels matched #89B4FA on winver's 165x50 menu even though the [border] line read color=FF89B4FA useDefault=0 useNone=0. The order is not stable, which is why the ring was present on 13/10 and gone on 17/10 at 6:58 PM.

### Fix (30-engine.inc, 0.6.34)
1. The MENU_POPUPBORDERS branch records the rect it paints: state->outlineRect = clipRect. That rect is authoritative for the menu being painted; a buffered paint can resolve a different menu window, whose size would reserve the wrong ring.
2. HandleMenuDrawThemeBackground still stops the fill one pixel inside outlineRect, and now re-frames the full window rect after every band, with the clip dropped for the frame only (DcStateGuard). The outline therefore sits on top of whichever band painted last. Framing the band's own clip is what used to leave a tick at each band's right edge.
