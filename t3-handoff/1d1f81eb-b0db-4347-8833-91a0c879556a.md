### 3. Why it zooms (the key finding)

The `Indeterminate` visual state contains a `Storyboard RepeatBehavior="Forever"`:
- Bar 1: TranslateX from ContainerAnimationStartPosition → EndPosition over 1.5s
  (KeySpline `0.4,0,0.6,1`), discrete hold to 2.0s, then repeat.
- Bar 2 (trailing): delayed — starts at 0.75s, ends at 2.0s.
- Animation targets `(UIElement.RenderTransform).(CompositeTransform.TranslateX)` — it lives in the
  control TEMPLATE, so **no property setter (styler) can retime, slow, or reshape the motion**.
  The only ways to change the motion: replace the whole ControlTemplate (experimental, not practical
  via the styler) or make the moving bars invisible and show something static instead.

### 4. Styler capability facts (verified against config + template)

- State-scoped styles work via `Element@StateName` — but the states live on `Grid#LayoutRoot`
  (the template root), NOT on the ProgressBar control itself. So state-scoped rules must target
  `... > Grid#LayoutRoot@Indeterminate` or deeper. You CANNOT state-scope the ProgressBar's own
  geometry (Height@Indeterminate on the control will not fire). This kills a "hairline when
  indeterminate, pill when determinate" hybrid.
- Per-state FILL colors are possible and cheap: `Fill@Error`, `Fill@Paused`,
  `Fill@IndeterminateError`, `Fill@IndeterminatePaused` (the last two animate bar 2 — the current
  config does NOT cover them, so indeterminate pause/error currently falls back to accent).
- The styler supports `@GroupName` too (config uses `@CommonStates`, `@RunningIndicatorStates`).
