# 2026-11-12 Mixer 1.4.19: tray number smaller, inside the speaker's hover box, hidden over games

Owner asked: number closer to the speaker and a little smaller; it shows over a windowed
borderless game (same bug class as the media widget); it should hover like a real tray icon.

## Cause of the game overlap
The number is its own topmost layered window. It was shown whenever the tray icon had a rect,
so a borderless or fullscreen game that covers the taskbar (the taskbar drops below it) still
had the number floating on top. Same class as the visualizer/media widget (2026-10-10 note).

## Changes
- Mixer 1.4.18 -> 1.4.19:
  - Font 14 -> 12 px.
  - Shown only while `WindowFromPoint` at the speaker slot lands in `Shell_TrayWnd`
    (the number window is click-through, so the probe looks past it). Anything else on
    screen there (borderless game, fullscreen video, any covering window) hides it.
  - Re-checked on every foreground change (WinEvent hook, out of context, unhooked on
    destroy) and on the sync timer, now 500 ms instead of 1000 ms.
  - Placed inside the widened slot, 3 px left of the speaker glyph.
- Styler (backup `backups\2026-11-11-volmixer-1418\styler.reg.bak-20261112-0018`):
  - Rule 64: `Margin=30,0,0,0` -> `Width=52` on the speaker's NotifyIconView, so its own hover
    box, pressed state and click area take in the number.
  - Rule 65 (new): the speaker's ContentPresenter `HorizontalAlignment=Right`, `Margin=0,0,6,0`.

after); a second bump applied the rules. The script now bumps again after the install.

nothing; the script deletes through the raw registry key.
